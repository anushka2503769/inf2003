# INF2003 performance results (WP-10)

Generated by `bash backend/scripts/run_benchmark.sh` on 2026-10-27. Every number below was measured on throwaway local Docker databases seeded with synthetic data; nothing is estimated. See [README.md](README.md) for how to run it and how to read the tables.

## Machine and context

- CPU: Apple M5 (10 logical cores), RAM 32 GiB
- OS: Darwin 25.5.0 (arm64)
- Docker Engine 29.8.0, Docker Desktop, 10 CPUs, 8319504384 bytes memory for containers
- PostgreSQL 16.15 (Debian 16.15-1.pgdg13+2) and MongoDB 7.0.45 in containers (postgres:16, mongo:7), default settings, no tuning
- Python 3.12.13, psycopg2 2.9.13, pymongo 4.18.1
- Timing: 3 warm-up calls, then 30 timed calls per row; median and p95 (linear interpolation) in milliseconds. Random seed 20261026.

Every phase ran once and is reported, in the order run, with no selection. Median and p95 are over successful requests only. Diagnostics per phase: PostgreSQL sessions are `client backend` rows in `pg_stat_activity`, sampled once a second over a separate connection that can itself fail; a maximum is shown only when at least half the expected samples were obtained, and "not measured" otherwise. TIME_WAIT is the host's `netstat` count.

|---|---|---|---|---|---|---|

| without shared read lock | 13 / 100 | 30 of ~30 samples | 16 | none | none | none |

#### Control: raw connection storm, no application code (10 threads, 30 s)

| Pattern | Successful iterations | Failed connection attempts | Seconds into the phase when failures occurred | Connections/s (successful) | Most common failure |
|---|---|---|---|---|---|
| 2 nested connections per iteration (the lock path's pattern) | 4655 | 0 | none | 310 | none |
| 1 connection per iteration (the no-lock path's pattern) | 6284 | 6972 | [0.0, 10.6] | 209 | OperationalError: connection to server at "127.0.0.1", port N failed: server closed the connection unexpectedly |
| 2 nested connections per iteration (repeat) | 3024 | 7844 | [10.6, 23.1] | 201 | OperationalError: connection to server at "127.0.0.1", port N failed: server closed the connection unexpectedly |

Each worker is a keep-alive `httpx` client for one seeded user and picks one of three Discover queries (no filter, broad filter, selective filter) at random. The server is the real FastAPI app on a free `127.0.0.1` port, identity-checked before load starts, with unsigned development tokens; the "without" run replaces the route's lock with a no-op.
